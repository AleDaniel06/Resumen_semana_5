Database Engine — Motor de BD

Núcleo de SQL Server. Almacena, procesa y protege los datos.

  • Gestión de tablas, vistas, índices y restricciones
  • Procesamiento transaccional con propiedades ACID
  • Seguridad robusta con control de usuarios y roles
  • Recuperación ante fallos y copias de seguridad
  • Escalabilidad horizontal en múltiples servidores

SSAS — Analysis Services

Plataforma OLAP. Crea y gestiona cubos de datos multidimensionales.

  • Cubos con tablas, gráficos y grillas de datos
  • Diseñador visual + lenguaje de consulta MDX
  • Integración con Excel, SharePoint y Power BI
  • Programación con Visual C# o Visual Basic

SSRS — Reporting Services

Genera, publica y administra informes en línea y en papel.

  • Informes estáticos o interactivos (tablas, gráficos, grillas)
  • Diseñador visual + lenguaje RDL
  • Publicación por portal web o correo electrónico
  • Integración con SQL Server y SharePoint

SSIS — Integration Services (ETL)

Plataforma ETL (Extract, Transform, Load) para integración y migración de datos.

  • Conecta BD relacionales, CSV, Excel y servicios web
  • Transformación: limpiar, combinar y manipular datos
  • Migraciones de sistemas y soluciones Data Warehouse
  • Automatización de tareas y procesos de negocio

📚 Preguntas Teóricas
1

En un sistema bancario OLTP, ¿qué pasaría si no se garantizan las propiedades ACID?

Sin ACID: Atomicidad: una transferencia puede debitarse sin acreditarse → pérdida de dinero. Consistencia: saldos en estados inválidos (negativos no autorizados). Aislamiento: dos retiros simultáneos del mismo saldo = doble gasto. Durabilidad: transacciones confirmadas pueden perderse ante fallas. Consecuencia: pérdida de integridad financiera, confianza y violación de normativas (PCI-DSS, Basilea III).
2

¿Cómo se diferencian OLTP y OLAP en proyectos empresariales?

OLTP: gestiona operaciones diarias (ventas, pagos, inventarios) en tiempo real — esencial para ERP y POS. OLAP: sirve para análisis estratégico (tendencias, segmentación, rendimiento regional) sobre datos históricos. En arquitectura completa: OLTP → SSIS (ETL) → Data Warehouse → SSAS → SSRS. Son complementarios, no competidores.
3

¿Qué beneficios aporta un Data Warehouse en una empresa de e-commerce?

1. Visión 360° del cliente (compras + navegación + soporte). 2. Análisis de tendencias por temporada/región. 3. Optimización de inventario con patrones históricos. 4. Segmentación B2C/C2C para campañas personalizadas de alto ROI. 5. Decisiones ejecutivas basadas en datos, no intuición. 6. Integración de OLTP + CRM + plataformas de pago en un solo análisis.
4

¿Por qué SQL Server 2022 es considerado una plataforma híbrida en la nube?

Porque opera simultáneamente en: On-premises (Windows/Linux), nube pública (Azure SQL Database / Managed Instance) y nube híbrida (Azure-SSIS Integration Runtime ejecuta ETL en la nube con datos locales). Beneficios: migración gradual sin interrupciones, escalado dinámico, IA de Azure integrada, y disaster recovery con réplicas en nube.
5

¿Qué riesgos existen si se usa SQL Server Express en producción crítica?

1. Almacenamiento limitado a 10 GB por BD. 2. Sin SQL Agent → sin backups automáticos = riesgo de pérdida de datos. 3. Solo 1 GB RAM y 1 socket CPU → cuellos de botella bajo alta concurrencia. 4. Sin Always On ni clustering → cero tolerancia a fallos. 5. Sin SSAS/SSIS completos → capacidades BI mínimas. 6. Sin soporte técnico Microsoft. Express es solo para desarrollo y aprendizaje.
6

¿Qué diferencia hay entre SQL Server Developer Edition y Enterprise Edition en un proyecto académico?

Son técnicamente idénticas — Developer tiene toda la funcionalidad de Enterprise. La diferencia es de licenciamiento: Developer es gratuita pero prohibida en producción (solo prueba/desarrollo). Enterprise tiene licencia comercial por core (costo muy elevado). Para proyectos universitarios: Developer Edition es la elección correcta y ética — sin violar el EULA de Microsoft.
7

¿Por qué los sistemas de BI requieren SSAS (Analysis Services)?

1. Análisis multidimensional en cubos desde múltiples perspectivas simultáneas (imposible en SQL simple). 2. Rendimiento superior: cubos pre-calculan agregaciones → consultas en segundos vs. minutos en SQL. 3. Lenguaje MDX para consultas analíticas complejas. 4. Integración nativa con Excel, Power BI y SharePoint. 5. Definición de KPIs directamente en el modelo de datos.
8

¿Qué papel cumple SSRS en un sistema de gestión hospitalaria?

1. Reportes clínicos: historial médico y tratamientos en PDF/web. 2. Estadísticas de ocupación: camas, tasa de internamiento por área. 3. Gestión financiera: facturación, seguros, cuentas por cobrar. 4. Control de medicamentos: inventario y alertas de vencimiento. 5. Indicadores de calidad (SUSALUD): infecciones, readmisiones, tiempos de espera. 6. Distribución automática de reportes a directivos por correo o portal.
9

¿En qué escenarios preferir SSIS frente a consultas manuales de integración?

SSIS es preferible cuando: 1. Se integran múltiples fuentes heterogéneas (BD + CSV + Excel + APIs). 2. Se requieren transformaciones complejas (limpiar, deduplicar, validar). 3. El proceso se repite automáticamente sin intervención humana. 4. Se manejan millones de registros. 5. Se necesita trazabilidad y auditoría de cada ejecución. 6. Migraciones de plataforma con historial complejo. Regla: si el ETL se repite o tiene múltiples fuentes → SSIS siempre.
10

¿Cómo influye la elección de edición de SQL Server en un proyecto de transformación digital?

1. Escalabilidad: Enterprise crece sin límites; Standard tiene restricciones. 2. IA: solo Enterprise incluye machine learning integrado. 3. Costo (TCO): Enterprise puede ser decenas de miles de dólares por core — elegir mal eleva el presupuesto irracionalmente. 4. Alta disponibilidad (Always On): solo Enterprise y Standard (limitado). 5. Cumplimiento GDPR/HIPAA: seguridad avanzada solo en ediciones superiores. Roadmap natural: Express → Developer → Standard → Enterprise.
💻 Preguntas Prácticas
1

Conectarse a SQL Server en la nube con dominio empresa.com. ¿Qué valor colocar en Nombre del servidor?

Colocar el dominio completo: empresa.com
Si es Azure SQL: empresa.database.windows.net
Autenticación: SQL Server Authentication o Azure Active Directory (no Windows Auth para servidores en la nube).
2

¿Cómo registrar un servidor local en el panel Servidores registrados de SSMS?

1. Ver → Servidores Registrados. 2. Expandir Motor de base de datos. 3. Clic derecho en Grupos de servidores locales → Nuevo registro de servidor. 4. Nombre del servidor: localhost o . 5. Autenticación de Windows. 6. Clic Probar → Guardar.
3

Proyecto de migración: verificar usuarios en msdb. ¿Qué consulta ejecutar?

USE msdb
GO
SELECT * FROM sys.sysusers
GO
sys.sysusers retorna todos los usuarios de la BD actual con nombre, id, tipo y SID.
4

¿Qué instrucción analiza qué objetos contiene la base model?

USE model
GO
EXECUTE sp_help
GO
sp_help sin parámetros lista todos los objetos de la BD actual: tablas, vistas, procedimientos, funciones y tipos de datos. model es la plantilla base para nuevas BD.
5

Mostrar las tablas de la base Northwind en SSMS. ¿Cómo?

Visual: Explorador de Objetos → Northwind → Tablas.
T-SQL:
USE Northwind
GO
SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES
WHERE TABLE_TYPE = 'BASE TABLE'
ORDER BY TABLE_NAME
6

¿Cómo cargar y ejecutar el script instnwnd.sql para crear Northwind?

1. Archivo → Abrir → Archivo. 2. Navegar a carpeta DB → seleccionar instnwnd.sql → Abrir. 3. Presionar F5 o clic en Ejecutar. 4. Esperar ejecución completa. 5. Explorador de objetos → clic derecho en Bases de datos → Actualizar. 6. Verificar que aparece Northwind en la lista.
7

¿Qué consulta ejecutar para conocer la versión de SQL Server instalada?

-- Versión completa
SELECT @@VERSION

-- Detallado (para informes)
SELECT SERVERPROPERTY('ProductVersion') AS Version,
SERVERPROPERTY('Edition') AS Edicion
8

¿Cómo listar todos los procedimientos almacenados de Northwind en SSMS?

USE Northwind
GO
SELECT name, create_date, modify_date
FROM sys.procedures
ORDER BY name
Visual: Explorador → Northwind → Programación → Procedimientos almacenados.
9

Proyecto de auditoría: verificar el modo de autenticación del servidor. ¿Cómo?

Visual: Explorador → clic derecho en el servidor → Propiedades → Seguridad → Autenticación del servidor.
-- 1 = Solo Windows · 0 = Modo Mixto
SELECT SERVERPROPERTY('IsIntegratedSecurityOnly') AS SoloWindows
10

¿Cómo identificar la RAM del servidor donde corre SQL Server?

-- RAM total del sistema
SELECT total_physical_memory_kb / 1024 AS RAM_Total_MB,
available_physical_memory_kb / 1024 AS RAM_Libre_MB
FROM sys.dm_os_sys_memory

-- RAM en uso por SQL Server
SELECT physical_memory_in_use_kb / 1024 AS RAM_SQL_MB
FROM sys.dm_os_process_memory
Visual: Propiedades del servidor → General → Memoria.

Microsoft SQL Server 2022

RDBMS desarrollado por Microsoft — la versión más reciente. Ofrece mejoras sustanciales frente a versiones anteriores.

Plataformas: Windows · Linux · Nube (Azure) — verdadera plataforma híbrida.

Novedades v2022:

  • IA integrada con Azure Machine Learning
  • Seguridad mejorada y control de acceso granular
  • Mayor escalabilidad horizontal
  • Rendimiento optimizado con nuevo motor de consultas
  • Soporte nativo para cargas de trabajo en la nube

OLTP — On-Line Transaction Processing

Técnica de procesamiento de transacciones en tiempo real para gran volumen de operaciones pequeñas y rápidas.

Propiedades ACID: Atomicidad · Consistencia · Aislamiento · Durabilidad
  • Transacciones procesadas inmediatamente
  • Alta concurrencia de usuarios simultáneos
  • Alta velocidad de acceso a los datos
  • Arquitectura de BD relacional normalizada

Casos de uso: Bancos, aerolíneas, tiendas en línea, sistemas POS.

OLAP — On-Line Analytical Processing

Técnica para analizar grandes volúmenes de datos multidimensionales organizados en cubos.

Estructura: Cubos con dimensiones (tiempo, producto, región) que permiten análisis desde múltiples perspectivas simultáneas.
  • Gran volumen de datos históricos
  • Consultas complejas y analíticas (MDX)
  • Arquitectura multidimensional
  • Pre-cálculo de agregaciones para alta velocidad

Casos de uso: Business Intelligence, finanzas, reportes ejecutivos estratégicos.

Data Warehouse — Almacén de Datos

Sistema de almacenamiento diseñado para soportar el análisis y la toma de decisiones estratégicas.

Fuentes: Sistemas transaccionales + CRM + ERP + fuentes externas → integrados en un solo repositorio vía SSIS.
  • Datos históricos consolidados de múltiples fuentes
  • Arquitectura dimensional (estrella o copo de nieve)
  • Optimizado para consultas analíticas complejas
  • Diferente a BD transaccional: análisis, no operaciones
